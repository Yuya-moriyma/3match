# dev task plan

## workflow

### Step 0: 計画書確認
指示された作業に関する計画書があるかどうかを確認する。
計画所が存在する場合はユーザーに実施確認を行ってからStep 5を実施する。

### Step 1: 関連ソースコード分析
開発タスクに関連しそうなソースコードを解析し、現在の情報を把握する。
同時に現在起動している開発用のdocker環境の状態や環境変数も確認する。

### Step 2: 作業内容把握
指示された作業がどのような内容なのかを分析し、要件を洗い出す。
曖昧で作業指示から予測、補完が難しい内容や、現在のソースコードを含めた
前提条件と矛盾がある場合はユーザーに確認する。
作業内容が新規作成を伴わず、軽微なソースコードの修正で実現できる場合は即時に実施し、作業を終了する。

### Step 3: 計画書ファイル出力
作業計画内容を.claude/plansにファイル出力する。
ファイル名には日付時刻のprefixをつける。
ファイルには具体的なソースコードは極力記載せず、概念やルール、観点を文章で記載する。
その説明の為にフォーマットされた特定の記法を使用するのは許可。
計画の際はarchitecture-designも参考にする
また、進捗管理表でもあるため、各フェーズの進行状況を随時書き込む。

### Step 4: 計画書レビュー
これまでの会話履歴をすべて忘れ、改めて計画書とその内容が妥当かどうかレビューをする。
必要に応じて現在のソースコードとも比較する。
architecture-designやfrontend-designなどデザインガイドラインに沿っているかも確認する。
レビューが完了したら、計画書の修正を行う。
修正が完了できたら、最初のユーザーの命令に自動実施してよいという指示がある場合はSTEP5を実施する。
そうでない場合は、一度作業を終了する。（STEP5は実施しない）

### Step 5: 作業実施
計画書に沿って作業を実施する。
作業実施時はdev-task-exeスキルを使用する。
